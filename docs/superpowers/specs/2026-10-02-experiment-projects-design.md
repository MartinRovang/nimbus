# Experiment projects

## Goal

Point Claude at one repo with "edit these files, run this command, this number should go down (or up)" and leave it running unattended. It commits each try, keeps the improvements, resets the rest and logs every try. You come back to a table of experiments and a better branch.

This is [karpathy/autoresearch](https://github.com/karpathy/autoresearch) with the ML specifics removed: any command that prints a number can be the metric.

## Decisions

- An experiment is a **kind of project**, not a new subsystem. It reuses the project folder, the worktree on its own branch, the generated `CLAUDE.md`, the terminal and the sidebar's working / waiting / done marks.
- **Claude runs the loop itself** in a terminal, as in autoresearch. Nimbus does not supervise iterations.
- Nimbus writes a **fixed harness** (`run.sh`) that runs the command and reports the metric. Claude may not edit it, so it cannot redefine the metric or flood its context with output.
- Unattended running comes from a **scoped allowlist**, not from skipping permissions. Anything outside it prompts and pauses the loop.
- One repo per experiment, one loop per project.

## Config (`.nimbus-project.json`)

An experiment has `kind: "experiment"` and an `experiment` object. Projects without `kind` are phase projects, as today.

```json
{
  "kind": "experiment",
  "goal": "cut parse time",
  "repos": ["demo@faster-parse"],
  "experiment": {
    "files": ["src/parse.rs"],
    "command": "cargo bench parse",
    "metric": "time:\\s+([\\d.]+)",
    "direction": "lower",
    "budget": 300
  }
}
```

- `files`: globs relative to the repo, the only files Claude may edit.
- `command`: run with `sh -c` in the repo's worktree.
- `metric`: a regex with one capture group, matched against the command's output; the last match wins. Empty means the last number in the output.
- `direction`: `lower` or `higher`.
- `budget`: seconds. A run past it is killed and counts as a crash.

No `phase` and no `report` for an experiment.

## The dialog (`NewProject` in `src/Overlays.jsx`)

A Phases / Experiment switch at the top, shown only when starting a project (not when adding repos to one). Experiment replaces the repo multi-select with a single repo choice, hides "Claude reports back on", and adds the fields above: editable files (one glob per line), run command, metric regex, direction, budget in minutes (default 5).

Start is disabled until there is a name, a repo, at least one file glob, a command and a metric regex that compiles with exactly one capture group (or is empty). File globs become permission rules, so one that starts with `/` or contains `..` is refused.

## Files Nimbus writes into the project folder

All written once, at creation. The worktree is linked into the folder as `<repo>/`, as for any project.

### `run.sh` (mode 755)

Generated by a pure function `runSh(experiment, repoDir)` in `src/lib.js`.

- `cd` into the worktree and run the command under `timeout <budget>`, with stdout and stderr going to `run.log` in the project folder.
- Extract the metric from `run.log` with the regex's capture group (`perl -ne`, last match; or the last number when the regex is empty).
- Print exactly one of:
  - `metric: <number>` on exit 0 with a match
  - `crash: timeout` when `timeout` killed it
  - `crash: exit <code>` or `crash: no metric`, each followed by the last 40 lines of `run.log`
- The command and regex are embedded single-quoted, with the same quoting `claudeCmd` uses.

### `CLAUDE.md`

Generated by `experimentMd(p)` in `src/lib.js`. Sections:

- **Setup**: the repo, its branch, the editable files, what the metric is and which direction is better. Read the editable files and the goal before starting.
- **Rules**: edit only the listed files. Do not edit `run.sh`, install packages or change how the metric is produced. All else equal, simpler wins: a tiny gain that adds ugly code is not worth keeping, an equal result from less code is.
- **Loop**, forever:
  1. Read `results.tsv` and `git log --oneline -20` in the repo. This is how you recover after your context is compacted.
  2. First run ever: change nothing, run, record as `baseline`, status `keep`.
  3. Make one change, commit it in the repo.
  4. `./run.sh` from the project folder.
  5. Append a row to `results.tsv`.
  6. Better than the best kept metric: keep the commit. Equal or worse, or a crash you can't fix in a couple of tries: `git reset --hard <last kept commit>`, the hash of the newest `keep` row.
- **Never stop** to ask whether to continue. Out of ideas: re-read the files, combine near-misses, try something more radical.

### `results.tsv`

Header row only at creation: `commit	metric	status	description`.

- `commit`: short hash. `metric`: the number, empty for a crash. `status`: `keep`, `discard` or `crash`. `description`: one line, no tabs.
- It lives in the project folder, outside the worktree, so `git reset` never touches it and it is never committed.

### `.claude/settings.json`

Generated by `experimentSettings(experiment, repoName)`. `permissions.allow` holds:

- `Edit` for each editable glob, both as `<repo>/<glob>` and by the worktree's absolute path (the worktree is a symlink out of the project folder), and for `results.tsv`
- `Bash(./run.sh)`
- `Bash(git -C <repo> <sub>:*)` for `status`, `diff`, `log`, `show`, `add`, `commit`, `reset`

`CLAUDE.md` tells Claude to use exactly these command forms, so they match the rules.

`env` sets `BASH_DEFAULT_TIMEOUT_MS` and `BASH_MAX_TIMEOUT_MS` to the budget plus 30 seconds. Claude Code's Bash tool otherwise stops waiting after 2 minutes, before a default 5-minute run has printed its metric. Confirmed with a real 135-second run.

The rules alone are not enough: the worktree is a symlink out of the project folder, and Claude Code refuses edits outside its working directories whatever the rules say. A real run showed `permissions.additionalDirectories` in the project's settings is ignored, while `--add-dir <worktree>` on the command line works. So Nimbus starts an experiment's Claude with `--add-dir` (`claudeCmd`'s third argument), both on creation and from "Start Claude here…". A `claude` typed by hand in the project folder will be asked about each edit. The `mcp__nimbus` tools stay allowed through `claudeCmd` as now.

## Rust (`src-tauri/src/lib.rs`)

`save_project` accepts only `CLAUDE.md` and `.nimbus-project.json` today. It gains a fixed list of the other project files: `REPORT.html`, `REPORT.json`, `run.sh`, `results.tsv`, `.claude/settings.json`. It creates `.claude/` when needed and sets `run.sh` to mode 755. Any other name is still refused.

(`saveProject` already passes `REPORT.html` and `REPORT.json` for HTML-report projects, which this check appears to refuse. The list fixes that too; confirm the current behaviour before relying on it.)

No new commands. The results view reads `results.tsv` through `read_file`.

## Starting and resuming

- `saveProject` in `src/App.jsx` branches on the kind: it builds the experiment's files instead of `projectMd` and the report seed, then starts Claude with `EXPERIMENT_START`: "Read CLAUDE.md, then start the experiment loop."
- "Start Claude here…" on an experiment project prefills `EXPERIMENT_RESUME` instead of `KICKOFF`: "Read CLAUDE.md, results.tsv and the git log, then carry on with the experiment loop."
- Stopping is closing the terminal.

## The results view (`src/Main.jsx`)

For `kind: "experiment"`, the project page's report tab renders a new `Experiment` component instead of the issue body or `REPORT.html`. The phase stepper is hidden. The Diff tab and other `.html` pages work as now.

Data comes from two pure functions in `src/lib.js`:

- `parseResults(tsv)` → `{ rows, skipped }`. A row needs four tab-separated fields, a known status, and a numeric metric unless it is a crash. Others are counted in `skipped`.
- `resultStats(rows, direction)` → `{ baseline, best, change, kept, discarded, crashed, frontier }`, where `frontier` is the best kept metric after each row.

The component shows:

- A header line: best metric, change against the baseline in percent, counts of kept / discarded / crashed, and "N rows skipped" when there are any.
- A chart, inline SVG: one dot per experiment (kept, discarded and crashed told apart by colour and shape), with `frontier` drawn as a stepped line. Crashes sit on the baseline of the plot. No animation and no CSS filters.
- The table, newest first: commit, metric, status, description. Hashes are plain text: Nimbus has no view of a single commit's diff today, and the project's Diff tab already shows everything kept against main.
- Before the first row: "No results yet: Claude records the baseline after its first run."

It refreshes on the project page's existing 10 s poll.

## Stalls and errors

- A command outside the allowlist prompts. The sidebar shows *waiting* and the existing notification fires. The loop pauses until you answer.
- A malformed `results.tsv` row is skipped and counted, never a blank page.
- A long run fills Claude's context and it compacts. Step 1 of the loop is what it recovers from.

## Testing

`src/lib.test.js`:

- `parseResults`: good rows, a crash row with no metric, short rows, an unknown status, a non-numeric metric, an empty file, header only.
- `resultStats`: baseline, best and frontier for both directions; crashes and discards never move the frontier.
- `runSh`: a command and a regex containing single quotes survive quoting.
- `experimentSettings`: the allow list for a sample config.
- `experimentMd`: names the repo, the files and the direction.

`src-tauri` (`cargo test`): `save_project` writes `run.sh` executable and `.claude/settings.json` in its folder, and still refuses an unlisted file name.

One script-level check, run from `npm test`: a generated `run.sh` against a fake command gives `metric: 1.5`, `crash: exit 3`, `crash: no metric` and `crash: timeout`.

## Out of scope

- More than one repo per experiment, or several agents on one experiment.
- Reporting an experiment on a GitHub issue.
- Nimbus driving the loop itself (`claude -p` per iteration).
- A switch to skip all permission prompts.
- Editing an experiment's settings after creation, other than by hand in the project folder.
