# Writer projects

## Goal

Start a project whose work is a text meant to be read: documentation, a guide, an article. Claude writes and revises with you, and the project page shows how the text changed, word by word, the way tracked changes do in a word processor.

## Decisions

- A writer project is a **kind of project**, not a new subsystem. It reuses the project folder, the worktree on its own branch, the generated `CLAUDE.md`, the terminal and the sidebar's working / waiting / done marks.
- The view shows **tracked changes only**. It does not judge the writing: no grammar findings, no readability numbers.
- Word-level changes come from **`git diff --word-diff=porcelain`**. No diff library and no diff algorithm of our own.
- The text is shown as **readable source**, not rendered Markdown. Marking changes inside rendered Markdown is a much larger job.
- The project is **focused on the text, not limited to it**. Claude may change code when the writing needs it (a doc build, an example that must run, a link checker). Those changes show in the normal Diff tab.
- The view is **read-only**.

## Config (`.nimbus-project.json`)

A writer project has `kind: "writer"`. It has no `phase` and no `report`.

```json
{
  "kind": "writer",
  "goal": "User guide for the installer, for people who have never used a terminal",
  "repos": ["docs@installer-guide"],
  "files": ["src/pages/*.jsx", "locales/en.json"]
}
```

`files` is optional: git pathspecs for where the text lives when it is not in the usual text files, for example the pages of a frontend. Without it the view covers the prose files below.

It may span several repos, like a phase project.

## New project dialog (`src/Overlays.jsx`)

`NewProject` gains a third choice, "Writing", next to project and experiment. It shows name, repos and goal. Where the text lives is not asked here: Claude settles it with the user in the first conversation and writes `files` to the project file. The goal's hint asks what the text is and who reads it. The report choice (issue or HTML) and the experiment fields are hidden.

`saveProject` in `src/App.jsx` gets a third branch: `writerMd(p)` for `CLAUDE.md`, the config above, and no other files.

## `CLAUDE.md`

Generated by `writerMd({ name, goal, repos })` in `src/lib.js`. It carries the same `<!-- nimbus:repos -->` block as `projectMd`, so `withRepos` keeps working when repos are added. Sections:

- **What this is**: a writing project. The goal, the repos and their branch.
- **Where the text lives**: the Text tab shows the usual text files unless `files` in `.nimbus-project.json` says otherwise; when the text is elsewhere, agree the files with the user and set it. The reader is whoever the goal names; write for them.
- **Focus**: the work is the text. Change code when the text needs it, and say so when you do; do not go looking for code to improve.
- **Revisions**: commit each revision on its own, in the repo, with a message that says what changed in the writing ("Tighten the install section", "Reorder: prerequisites first"), not "update docs". The project page steps through these commits, so one commit should be one readable step.
- **Report**: keep the workfolder report current through the Nimbus tools, as in any Nimbus terminal. There is no `REPORT.html`.

## Starting and resuming

A new writer project starts Claude with `WRITER_START`: "Read CLAUDE.md and the texts in the repos, then ask me what is unclear about the text and its reader before you write." "Start Claude here…" on an existing one uses `WRITER_RESUME`: "Read CLAUDE.md and the git log of the repos, then tell me where the text stands and what you would revise next." Both go through `claudeCmd` as now; no `--add-dir`, no allowlist.

## The view (`src/Writer.jsx`)

`ProjectTab` in `src/Main.jsx` returns `<Writer repos={repos} n={n} height={height} />` when there is no tab and `cfg.kind === "writer"`, the way it returns `Experiment`. The Diff tab stays, for code. `ProjectWindow` loads repos for this tab as it does for `:diff`, so the view pops out to the other screen.

### Text files

The project's `files` when it has them, otherwise the default pathspecs: `*.md`, `*.mdx`, `*.markdown`, `*.txt`, `*.rst`, `*.adoc`, `*.tex`. Everything else belongs to the Diff tab.

A file that is not one of the default types (a `.jsx` page, a `.json` of strings) is shown in the mono font at full width, without the heading rule, since it is source with text in it.

### Modes

A segmented control, as in the file view:

- **Against main** (default): from where the branch left main (the same merge-base `ProjectDiff` computes; that helper moves out of `ProjectDiff` so both use it) to the working tree, uncommitted work included.
- **Step by step**: the branch's commits that touch prose, oldest first, from `git log --reverse --format=%h%x09%s <base>..HEAD -- <pathspecs>`. Previous and next buttons, "3 of 7", and the commit's message as the heading. When the working tree has prose changes, a last step "Not committed yet" follows the newest commit. Each step diffs `<sha>^` against `<sha>`; the last diffs `HEAD` against the working tree.

### Data

One call per repo and step:

```
git diff --word-diff=porcelain --no-renames -U99999 <from> [<to>] -- <pathspecs>
```

`splitDiff` (already in `src/lib.js`) splits the output per file. `parseWordDiff` turns one file's part into paragraphs.

An untracked text file is not in `git diff`. It is listed with `git ls-files --others --exclude-standard` and the same pathspecs, read with `read_file` and shown as all inserted, in "Against main" and in the "Not committed yet" step.

### `parseWordDiff(text)` in `src/lib.js`

Porcelain word-diff, after the `@@` header, is one token run per line: a leading space for unchanged text, `+` for inserted, `-` for removed, and a line holding only `~` for a newline in the source.

Returns `{ lines, added, removed }`. `lines` is an array of source lines, each an array of `{ t: " " | "+" | "-", s }`. `added` and `removed` count words (runs of non-whitespace) in the `+` and `-` runs. Header lines before the first `@@` are skipped; later `@@` lines are skipped too (with `-U99999` there is one hunk).

### Layout

- **Left**: the changed prose files, grouped by repo when there is more than one, each with `+added −removed` in words. A deleted file is listed struck through. Click to show it. The first file is selected on open.
- **Body**: the whole file in a reading column: the UI font rather than the mono one, about 70 characters wide, generous line height, `white-space: pre-wrap`. Inserted runs take `var(--add)` with an underline; removed runs take `var(--del)` with a line through. A line starting with `#` is set heavier, so headings read as headings. A line with no changed run is dimmed slightly when its file has changes elsewhere, so the eye finds the edits; this is one CSS rule and can go if it reads badly.
- **Empty**: "No text changes yet" when no prose file differs.
- Errors from git show in place, as in `ProjectDiff`.

## Rust

No change. `save_project` already accepts `CLAUDE.md` and `.nimbus-project.json`, and the view uses the existing `git` and `read_file` commands.

## Testing

`src/lib.test.js`:

- `parseWordDiff`: an unchanged line, a replaced word inside a line, an inserted paragraph, a removed line, the word counts, and the headers skipped.
- `writerMd`: carries the goal, the repos block and the commit-per-revision rule; `withRepos` still replaces its repos block.

The view itself is checked by hand in a real writer project: against main, stepping through commits, an untracked file, an uncommitted edit, and the popped-out window.

## Not in this version

- Rendered Markdown.
- Grammar and style findings, readability numbers.
- Editing or accepting / rejecting changes in the view.
- Moved-paragraph detection: a moved paragraph shows as removed in one place and inserted in another.
